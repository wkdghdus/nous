# M5 Nous Report Context Snapshot

## Task statement

Implement `.omx/plans/m5-nous-report-plan.md` under the Ralph completion and verification workflow.

## Desired outcome

A dependency-free Ruby CLI generates a deterministic, source-backed Markdown Nous report from reviewed notes and eligible canonical records, with focused regression coverage, repository check wiring, documentation, a generated default report, and fresh verification evidence.

## Known facts and evidence

- The approved plan defines `scripts/generate_nous_report.rb`, its CLI, report sections, filtering boundary, deterministic ordering, validation failures, atomic output, tests, docs, and verification commands.
- Existing maintenance CLIs use Ruby standard-library code, `OptionParser`, `Pathname`, `Psych`, explicit error handling, temporary fixtures, and Makefile wiring.
- M4 graph export already defines the reviewed/canonical discovery and filtering boundary to reuse locally.
- Generated Markdown reports belong under `vault/04_generated/reports/`; the default M5 destination is `vault/04_generated/reports/nous.md`.
- The worktree already contains a user-owned edit to `.omx/plans/AGENT.md` adding the M5 plan signpost; it must be preserved.

## Constraints

- Keep the implementation dependency-free, local-first, deterministic, and source-backed.
- Do not infer psychological conclusions or increase certainty beyond reviewed source records.
- Exclude inbox, rejected, deprecated, and archived records from active report output.
- Validate all included records before replacing an existing output.
- Keep changes surgical and do not extract shared helpers unless required.
- Ralph requires a canonical PRD and test specification before implementation, fresh verification, architect approval, a changed-files-only deslop pass, and post-deslop regression verification.

## Unknowns and resolved assumptions

- Canonical relationship presentation is not prescribed exactly. Use a compact related-records subsection only when both endpoints resolve to included report entries; silently omit dangling relationships.
- The current repository vault may contain no meaningful records. Generate the default report for verification, then retain it because the plan explicitly defines the default generated deliverable and empty sections are valid output.
- Evidence reference shapes may vary. Normalize common scalar/hash forms consistently with existing M4 behavior and preserve order after deduplication.
