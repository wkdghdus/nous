# M4 Graph Export Context Snapshot

Created: 2026-08-08T22:08:19Z

## Task Statement

Implement `.omx/plans/m4-graph-export-plan.md`.

## Desired Outcome

Add a dependency-free Ruby graph exporter that writes stable JSON graph records for reviewed notes, canonical claims, and canonical relationships. Wire it into tests, docs, and repository signposts, then verify with fresh test/lint evidence.

## Known Facts / Evidence

- The M4 plan requires `ruby scripts/export_graph.rb` with `--vault-root PATH`, `--output PATH`, deterministic JSON, and `NOUS_GRAPH_TIME` test override support.
- The repository uses standard-library Ruby scripts and script-level regression tests.
- `schemas/graph.schema.json` already defines `schema_version`, `generated_at`, `nodes`, and `edges`.
- Reviewed notes live under `vault/02_notes/*/*.md`.
- Canonical claims and relationships live under `vault/03_canonical_model/claims/` and `vault/03_canonical_model/relationships/`.
- Inbox records under `vault/01_agent_inbox/` must be excluded from the default export.
- `make test` currently runs ingestion and review queue tests; `make lint` checks JSON/YAML validity, final newlines, trailing whitespace, signposts, and scaffold boundaries.
- The repository vault currently contains only signposts and `.gitkeep` files in reviewed/canonical graph directories, so a default export may contain empty arrays.

## Constraints

- No new dependencies.
- Preserve reviewed-only semantics by default.
- Fail clearly for duplicate IDs, unsupported exported types, invalid confidence, malformed exported records, and dangling edge endpoints.
- Do not silently export rejected, deprecated, archived, pending, malformed, or inbox records as active graph records.
- Write output atomically only after validation passes.
- Keep diffs focused and reversible.

## Unknowns / Open Questions

- Whether the generated repository graph should be committed when the current vault has no reviewed/canonical records. The plan says to commit it only if meaningful, otherwise keep `.gitkeep` and document generation.
- Whether future canonical model directories beyond claims/relationships should become nodes. M4 scope limits export to reviewed notes plus canonical claims/relationships.
